# 能力：Cursor 工人模型钉死与档位展示

## 需求

### 需求：Cursor 引擎工人按指定模型启动

系统必须在启动 Cursor 引擎工人（含自定义工人）时，若存在指定模型，则在进程参数中带上该模型，而不是先按出厂模型开会话再改。

#### 场景：委派默认是 Composer 2.5

- **前置**：`cg-explore` 的委派默认模型为 `composer-2.5`
- **操作**：主会话委派任务给 `cg-explore`
- **期望**：该工人第一轮对话使用 Composer 2.5
- **禁止**：第一轮对话使用 Grok 4.6 或其他出厂模型

#### 场景：未指定模型时保持出厂

- **前置**：该 Cursor 引擎工人没有模型覆盖，也没有面板模型设置
- **操作**：启动该工人
- **期望**：不额外附加模型启动参数，行为与改前一致

#### 场景：非 Cursor 引擎不受影响

- **前置**：工人是 Codex 等非 Cursor 引擎
- **操作**：按该工人自己的默认启动
- **期望**：不会带上 Cursor 的模型启动参数

### 需求：Composer 上不展示、不套用 Effort

当用户当前选择的模型属于 Composer 家族时，设置页不得展示 Effort；开工时不得把 Effort 覆盖套到该会话。

#### 场景：设置页选 Composer 2.5

- **前置**：探测快照里有 Mode、Model、Effort、Fast；用户将模型覆盖设为 Composer 2.5
- **操作**：查看该工人的智能体默认表单
- **期望**：不出现 Effort 行；Fast 仍可出现
- **禁止**：暗示 Composer 拥有 Medium 等思考档

#### 场景：设置页选回 Grok 4.6

- **前置**：探测快照含 Effort；用户将模型覆盖改为 Grok 4.6 或恢复智能体默认且出厂是 Grok
- **操作**：查看表单
- **期望**：Effort 行重新出现

#### 场景：保存值里残留 Effort 但目标是 Composer

- **前置**：覆盖同时含 `model=composer-2.5` 与某个 Effort 值
- **操作**：委派启动该工人
- **期望**：按 Composer 启动，不把 Effort 套到该会话
